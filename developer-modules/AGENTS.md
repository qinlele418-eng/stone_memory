# 模块开发 Agent 必须遵守的入口契约

修改本目录前完整阅读 [DEVELOPMENT.md](./DEVELOPMENT.md)。MCP 的权威契约在
其中第 17 节；下面是开发与审阅时必须执行的规则。

1. 模块需要向 Agent 提供工具时，通过自身 `module.json` 的 `entry.mcp` 注册。
   使用 SDK v2 和最小权限，Provider、业务代码及测试放在模块目录内。
2. 不得给根 `mcp-server.js` 或 `src/mcp/core/` 增加模块专属工具、导入和路由
   分支；不得另起 stdio 服务、监听端口或要求用户手改客户端 MCP 配置。
3. 新模块使用宿主生成的命名空间，不编辑 `legacy-tool-names.js` 申请普通注册。
   该表仅处理已批准的旧 Core 名称迁移；宿主能力不足时先说明公共接口缺口。
4. `tools()` 同步返回完整定义，`call()` 返回标准 `CallToolResult`。memory
   工具必须显式选择记忆体，不默认第一项；启停只经正式模块 CLI，不能手写配置。
5. 只读查询不得初始化/迁移数据库或清理历史数据。写工具声明 `mcp:write`，
   通过 `context.runCommand` 调用本模块正式 CLI 命令，不在 Provider 内直接写库、
   写缓存或启动子进程。正文走私有 batch，不进入 argv 或日志。
6. 用临时 HOME/USERPROFILE、数据库和合成数据做真实 `tools/list`、`tools/call`
   回归，覆盖启用、停用、非法参数、未授权记忆体、异常和 CLI 写入边界。
   新模块测试默认放自身 `test/`；共享宿主契约与跨模块迁移测试放根 `test/`。
7. 迁移旧工具必须验证原名称/参数/结果的兼容或明确记录变化，删除原 Core
   定义与路由，检查重复入口与关闭后回退。仅证明新名字可注册不算迁移完成。

交付时说明新增/迁移的工具、权限、CLI 动作、兼容变化、实际测试结果，以及代码
是否仅本地修改、已提交或已推送。不得把合成规划器测试称为真实模型验收。
