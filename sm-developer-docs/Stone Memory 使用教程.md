# Stone Memory 新手教程：把旧对话真正变成 AI 的长期记忆

> 适用场景：Stone Memory 已安装完成，Codex 或 Claude Code 已经配置好 Stone Memory MCP。  
> 这篇教程从打开 Web 工作台开始，带你完成：创建记忆体 → 导入旧对话 → 挖掘记忆 → 接入线程 → 重建线程 → 让新上下文生效。

## 开始前，先理解这条流程

```text
导入旧对话
   ↓
挖掘成长期摘要
   ↓
把当前 AI 线程接入记忆体
   ↓
重建线程上下文
   ↓
Codex 重启 / Claude Code 切走再切回
```

只导入对话，并不等于 AI 已经在当前窗口里“想起来了”。

导入负责保存历史，挖掘负责把历史整理成记忆，线程重建才负责把这些记忆放回 AI 当前能看到的上下文里。

---

## 第 1 步：打开 Stone Memory 前端

在 Stone Memory 项目目录运行：

```bash
stmem web dev
```

默认地址：

```text
http://127.0.0.1:4173
```

如果页面要求 Web API Token，升级用户可以先运行：

```bash
stmem web auth claim
```

如果提示没有待领取的 Token，就创建一个新的：

```bash
stmem web auth rotate
```

Token 只会完整显示一次，复制后请妥善保存，不要发到截图、帖子或公开仓库里。

---

## 第 2 步：创建一个记忆体

打开首页，点击“创建记忆体”。

依次填写：

- 记忆体名字：方便你区分不同用途，例如“日常陪伴”或“编程搭档”。
- AI 名字与用户名字：让后续摘要能正确区分双方。
- 挖掘场景：决定系统整理记忆时重点关注什么。

常用场景包括：

- 生活监督：适合日常生活、计划与长期变化。
- 情感陪伴：适合关系、情绪和个人经历。
- 编程日志：适合项目决策、问题排查和开发进度。

点击“创建并进入”。

记忆体和聊天线程不是同一个东西：一个记忆体可以接入多个线程，线程只是 AI 当前工作的窗口。

---

## 第 3 步：导入以前的对话

进入刚创建的记忆体，按下面的路径打开导入页：

```text
记忆 → 记忆维护 → 数据导入
```

把对话文件拖进页面，或者点击“选择文件”。

当前可识别的来源包括：

- Claude Code
- Claude.ai
- Codex
- ChatGPT 官方导出
- 通用 JSON / JSONL
- SQLite

文件识别完成后，先检查页面展示的来源、对话数量和时间范围，再点击“导入当前记忆体”。

导入后的内容可以在这里检查：

```text
记忆 → 记忆档案 → 全量对话
```

如果这里能看到历史消息，说明旧对话已经进入记忆体；但此时它们仍然只是原始资料，还没有自动变成长期摘要。

---

## 第 4 步：在记忆挖掘台整理长期记忆

打开：

```text
记忆 → 记忆维护 → 记忆挖掘台
```

第一次使用、第一次重建线程之前，建议先把已导入的全部历史对话挖掘完成。

挖掘会从原始对话中生成两类内容：

- 摘要：发生了什么、形成了什么持续理解，以及相应时间和重要程度。
- 特征：值得以后继续追踪的人物、项目、习惯或长期概念。

如果历史对话很多，挖掘需要一些时间。等待任务完成后，抽查几个日期的摘要，确认人物、事件和时间没有明显识别错误。

你也可以在“摘要”里进一步调整：

- 原文锚点：重建时不只放摘要，还会带上对应原文。
- 事件锚点：保护重要事件，不让它被自动衰减或隐藏。
- 隐藏摘要：保留记录，但以后重建时不再注入线程。

小建议：不要给所有摘要都加原文锚点。真正需要逐字回看的关键事件才适合保留原文，否则重建后的上下文会重新变大。

---

## 第 5 步：把聊天线程接入记忆体

进入：

```text
接入 → 接入线程
```

页面会生成一段绑定指令。复制它，然后发送到你想接入的 Codex 或 Claude Code 窗口中，让 Agent 通过 Stone Memory MCP 完成绑定。

### 情况 A：绑定一个已经存在的线程

先在 Codex 或 Claude Code 中打开、恢复那个旧线程，再把绑定指令发给它。

适合：你希望继续使用原来的对话窗口，只是给它补上 Stone Memory 的长期记忆能力。

### 情况 B：绑定一个全新的线程

先新建一个 Codex 或 Claude Code 线程，再把绑定指令发给这个新窗口。

适合：旧线程已经太长、太乱，或者你想从一个更干净的上下文重新开始。

绑定成功后，回到“接入”页检查：

- 是否出现对应的 Codex / Claude Code Binding。
- 是否处于“监听中”。
- 多个 Binding 中，准备长期使用的窗口是否设成主 Binding。

绑定只是在记忆体和线程之间建立联系，不会自动改写当前线程已有的上下文。下一步才是让记忆真正进入线程。

---

## 第 6 步：重建线程

打开：

```text
上下文 → 线程重建
```

### 为什么需要重建？

Codex 和 Claude Code 的上下文来自它们正在读取的线程文件，而挖掘出的摘要保存在 Stone Memory 的记忆库里。

所以：

- 导入完成，只代表 Stone Memory 保存了原始对话。
- 挖掘完成，只代表 Stone Memory 整理出了长期记忆。
- 重建完成，才代表这些记忆被重新组织进目标线程的上下文。

线程重建不是简单地把所有旧聊天重新塞回去。它会用更节省上下文的方式，重新组合一份可继续使用的线程文件。

### 当前线程重建会放入什么？

- 当前记忆体的人设与规则。
- 没有被隐藏的历史摘要。
- 被设为原文锚点的重要原始对话。
- 最近若干个实际发生过对话的活跃日原文。
- 最近若干组完整工具调用及结果。
- 目标运行时所需的线程结构与元数据。

原文锚点和事件锚点会受到保护；隐藏摘要不会进入本次注入。

### 当前可以调整哪些内容？

点击“注入策略”，可以设置：

- 摘要范围：使用全部可见摘要，或限制数量和最低 importance。
- 近期上下文：按最近几个活跃对话日保留原文。
- 水位线模式：已经挖掘出摘要的旧原文不再重复注入，只保留水位线之后的内容。
- 工具链数量：保留最近多少组完整工具调用和结果。
- MCP 默认重建范围：让 Agent 以后通过 MCP 重建时复用这套摘要策略。

如果最近的工具调用对后续任务仍然重要，不要把工具链数量设成 0，否则 Agent 会失去这些调用及结果的上下文。

### 重建前还能做什么？

- 检查线程：只读检查线程结构，发现异常后再决定是否修复。
- 生成重建预览：先看数据来源、摘要数量、锚点原文、近期消息、工具链、预计文件大小和压缩率。
- 永久裁剪：从活动线程、archive 和 full 中永久移除选中的对话或工具链。这个功能不可逆，不是普通重建的必需步骤，新手不要随便使用。

Stone Memory 会先生成 dry-run 预览。确认内容无误后，再点击“确认应用线程重建”。正式应用前会备份原线程，并在写入后校验结构。

---

## 第 7 步：让重建结果真正生效

这一步 Codex 和 Claude Code 不一样，千万不要混用。

### 如果你用的是 Codex：应用后立刻完全重启

Codex 会立即写入重建后的线程文件。

看到“线程文件重建成功”后：

1. 不要继续在当前窗口发送消息。
2. 完全退出 Codex，包括仍在运行的 app-server。
3. 重新启动 Codex。
4. Resume 原来的线程。

```bash
codex resume <原线程 ID>
```

为什么一定要重启？因为旧 Codex 进程可能还握着重建前线程文件的旧文件描述符。继续聊天可能把新消息写回旧文件，造成重建结果没有生效，甚至丢失后续内容。

一句话记忆：**Codex 重建成功后，别再说话，立刻完全重启再 Resume。**

### 如果你用的是 Claude Code：走安全队列，再 switch

Claude Code 的活动线程不能在 MCP 调用还没返回时被同步替换，否则可能破坏消息 UUID 与工具结果之间的链路。

因此前端不会当场改写活动线程，而是显示“线程重建已排队”。接下来：

1. 先切换到另一个 Claude Code 线程。
2. 再切回刚才完成绑定的原线程。
3. Stone Memory 会在 MCP 重新载入时消费队列并应用重建。

也可以完全退出并重新启动 Claude Code，效果相同。

一句话记忆：**Claude Code 重建后走 switch：切走，再切回来。**

---

## 第 8 步：确认重建是否成功

重新进入线程后，回到 Stone Memory：

```text
上下文 → 当前上下文
```

重点检查：

- “上次重建”是否显示刚才的时间。
- “当前注入”是否出现人设 / 规则、摘要、近期与锚点原文、工具链数量。
- 线程文件是否显示“已定位”。

然后可以在 Agent 中问一个只有旧对话里才有答案的问题，观察它是否能结合历史记忆回答。

注意：不要只问“你还记得我吗”。最好问一个具体、可核对的问题，例如某个项目决定、长期习惯或曾经发生过的事件。

---

## 最容易踩的几个坑

### 1. 导入完就直接去聊天

导入只是保存原文。第一次使用还要完成：全量挖掘 → 接入线程 → 线程重建。

### 2. 挖掘完却没有重建

摘要已经在记忆库里，但当前线程文件没有变化，Agent 自然不会自动看到。

### 3. 重建了错误的 Binding

一个记忆体可以接入多个窗口。重建前检查“操作目标”，确认运行时和线程 ID 是你准备继续使用的那个窗口。

### 4. Codex 重建后继续在原进程聊天

不要这样做。立即完全重启，并 Resume 原线程。

### 5. Claude Code 排队后没有切换线程

排队不等于已经应用。切到其他线程再切回来，或者完全重启 Claude Code。

### 6. 给所有摘要都加原文锚点

这样很容易把线程重新撑大。普通经历保留摘要即可，真正需要逐字还原的内容再使用原文锚点。

---

## 最后用一句话总结

```text
创建记忆体 → 导入旧对话 → 挖掘全部历史 → 接入目标线程 → 预览并应用重建 → Codex 重启 / Claude Code switch
```

Stone Memory 做的是把原始对话、长期摘要和当前线程重新接成一条可以检查、可以维护、也可以继续生长的记忆链。
