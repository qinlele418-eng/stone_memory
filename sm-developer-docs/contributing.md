# 参与贡献

Stone Memory处于邀请制内测阶段。协作者可以补充文档、报告bad case并通过PR提交修复。

## 报告问题

Issue请包含：

- 使用的runtime：Claude或Codex。
- 执行入口：CLI、前端、MCP或watcher。
- 可以公开的复现步骤。
- 预期结果与实际结果。
- 错误日志中与问题直接相关的部分。

请先删除API Key、私人对话、真实线程文件、用户名和本机敏感路径。

## 提交文档

- 已验证的操作方式写入正式帮助文档。
- 模型对比、挖掘效果和压力测试写入 `test-reports/`，并使用目录中的统一模板。
- 尚未验证的新想法写入 `proposals/`。
- 不要把个人环境的临时补丁描述成所有用户都必须执行的标准步骤。
- 命令示例必须优先使用正式 `stmem` CLI。

## 提交代码

1. 从最新main创建分支。
2. 修改前阅读同目录 `AGENTS.md`。
3. 添加或更新回归测试。
4. 运行相关测试与完整 `npm test`。
5. 通过PR提交，不要直接推送main。

提交开发者模式前端前，还必须阅读 [前端实验模块规范](frontend-modules.md)。实验模块应使用独立目录和可拆卸 `bootstrap.js` 注册入口，不得在主 `app.js` 中硬编码卡片或模块页面。

PR说明至少包含：

- 修复或实现了什么。
- 为什么应该在这一层修改。
- Claude与Codex分别如何验证。
- 是否修改配置、SQLite、full或活动线程。
- 测试结果和回滚方式。
- 前端模块应额外说明 bootstrap 接入点、当前记忆体上下文来源，以及删除模块后的回滚验证。

## 不接受的改动

- 绕过CLI的第二套写入实现。
- 让用户或AI直接编辑SQLite、线程JSONL或 `stmem.json`的教程。
- 未经确认删除摘要、锚点、archive或full。
- 只为单个用户语料硬编码的词表和关系规则。
- 没有真实bad case、测试或解释的核心算法重写。
