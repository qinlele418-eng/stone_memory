# Stone Memory 主题小笔记使用说明

## 1. 主题小笔记是什么

「主题小笔记」是 Stone Memory 中用于整理独立 Markdown 笔记的开发者模块。

它适合保存不需要直接写进原始聊天记录、但希望长期整理和查找的内容，例如：

- 学习笔记；
- 开发记录；
- 旅行记录；
- 游戏攻略；
- 论坛资料；
- 测试记录；
- 日记和随笔；
- 其他 Markdown 内容。

笔记按照“主题”进行整理，可以继续编辑、搜索和管理。

---

## 2. 从哪里打开

进入 Stone Memory 的开发者模式后，可以通过「主题小笔记」对应的模块入口进入。

打开后即可查看当前记忆体中的主题和笔记。

主题小笔记具有自己的独立页面，不需要直接进入数据库或手动管理 Markdown 文件。

---

## 3. 主题和笔记

主题可以理解成一本笔记本。

例如：

**硬件开发**

里面可以有：

- ESP32 屏幕测试
- 电源模块调试记录
- PCB V2 修改记录

**数学建模**

里面可以有：

- 热管理模型思路
- 比赛论文修改记录
- 数据处理方法

每篇笔记保存独立的 Markdown 内容，可以继续编辑和追加。

---

## 4. 创建笔记

可以直接在主题小笔记页面创建主题和笔记。

在使用 Agent 时，也可以直接用自然语言描述自己想记录的内容，例如：

> 帮我把这次 ESP32 屏幕测试结果记下来。

Notebook 管家会先结合当前已有主题和笔记判断应该如何处理。

如果已经存在合适主题，可以优先放入已有主题；如果操作存在歧义，则应该先进行确认，而不是随意写入。

---

## 5. 让 Agent 管理笔记

日常情况下，主 Agent 可以通过：

```text
stmem_notebook_delegate
```

把自然语言需求交给 Notebook 管家处理。

因此用户不需要自己判断应该先调用搜索、读取还是写入工具。

例如可以直接说：

> 我之前记过 ESP32 屏幕的问题吗？

> 帮我找到之前的测试记录。

> 把今天的新测试结果追加进去。

> 把这篇笔记移动到另一个主题。

> 这篇不用了，删掉吧。

> 把刚才删除的笔记恢复回来。

Notebook 管家会先查找和定位笔记，再根据请求决定下一步操作。

---

## 6. 谁真正负责写笔记

这里比较容易产生误解。

Notebook 管家并不是一个拿着数据库写权限、可以随意修改文件的临时 Agent。

整体流程更接近：

**用户**

↓

**主 Agent**

↓

**Notebook 管家**

↓

**查询主题 / 搜索笔记 / 读取目标内容**

↓

**判断用户想做什么并生成操作计划**

↓

**Stone Memory 的 Notebook 执行逻辑**

↓

**真正完成写入或状态修改**

因此：

**管家负责“理解和管理流程”，执行层负责“真正写数据”。**

这也是为什么临时管家的工具可以主要保持为读取和定位能力，同时仍然能够帮助用户完成新增、修改、移动等完整操作。

---

## 7. 搜索笔记

主题小笔记提供笔记检索能力，可以根据现有条件查找内容。

可以利用例如：

- 关键词；
- 主题；
- 标签；

等信息缩小范围。

搜索结果独立展示，不需要为了搜索而改变原来的主题组织方式。

如果一次请求找到了多个很相似的候选对象，而系统不能确定用户指的是哪一个，应先让用户确认目标。

---

## 8. 修改已有笔记

已有笔记可以继续更新。

常见情况包括：

**追加**

在现有内容后继续增加新的记录。

例如：

> 把今天测得的温度数据追加到昨天那篇测试记录后面。

**修改 / 替换**

当用户明确希望修改现有内容时，对目标笔记进行更新。

为了避免多个操作互相覆盖，笔记具有 revision 版本校验。

可以简单理解成：

> Agent 读取的是第 5 版笔记，就不能在笔记已经被其他操作修改到第 6 版以后，仍然拿第 5 版的结果直接覆盖上去。

遇到这种情况时，应该停止原来的写入并重新获取最新状态。

---

## 9. 删除笔记和纸篓

纸篓主要用于**可恢复删除**。

例如现在有：

> ESP32 第一次屏幕测试记录

当用户说：

> 这篇没用了，删掉。

正常语义不是立即把 Markdown 文件永久销毁，而是把这篇已有笔记移动到纸篓。

因此用户之后仍然可以说：

> 我删错了，把那篇 ESP32 测试记录恢复回来。

系统再对原有笔记进行恢复。

纸篓适合以下情况：

- 删除写错的笔记；
- 清理重复笔记；
- 移除过时测试记录；
- 暂时清理已经不需要的内容；
- 误删后的恢复。

纸篓本身不是一个普通写作分类。

通常不会出现：

> Agent 专门新建一篇报告，然后主动把报告写进纸篓。

更合理的流程是：

**先存在一篇正常笔记 → 用户产生删除意图 → 原笔记进入纸篓 → 必要时恢复。**

---

## 10. 封存

主题小笔记还提供笔记封存相关能力。

封存和删除不是一回事。

**封存**

笔记仍然存在，但前端对正文的直接展示受到限制。

**纸篓**

表示这篇笔记已经被用户移除，但仍保留恢复能力。

所以可以简单理解为：

> 封存 = 还要留着，但暂时不正常展示。

> 纸篓 = 我现在不要它了，但先别彻底销毁。

---

## 11. CLI 与 MCP

主题小笔记不仅提供前端页面，同时也接入了 Stone Memory 的 CLI / MCP 能力。

因此可以通过不同入口访问 Notebook 功能：

- 前端页面适合人工浏览和编辑；
- CLI 适合开发、测试和明确的命令式操作；
- MCP 适合 Agent 调用；
- `stmem_notebook_delegate` 适合日常自然语言管理。

普通使用通常不需要手动组合所有低层工具。

---

## 12. 低层 Notebook 工具

Notebook 还存在用于状态、主题管理、写入、查询和读取的低层能力。

它们更适合：

- 开发；
- 调试；
- 验收；
- 数据修复；
- 精确控制某一步 Notebook 操作。

而日常聊天场景下，优先使用：

```text
stmem_notebook_delegate
```

通常会更简单。

目前讨论中的“普通模式 / 高级模式”工具开关仍属于后续设计方案，不代表当前版本已经具有该设置。

---

## 13. 使用时需要注意

当目标笔记不明确时，不建议让系统猜一篇直接修改。

当笔记 revision 已经变化时，不应继续使用旧版本覆盖。

删除操作优先进入纸篓，以保留恢复能力。

涉及高级调试时，再考虑直接使用低层 Notebook 工具；普通日常记录可以优先交给 Notebook 管家。
