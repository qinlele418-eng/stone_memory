# 社区测试报告

这里用于保存内测协作者提交的真实测试结果，例如：

- 不同模型的feelings/features挖掘效果对比。
- API与Subagent通道对比。
- 不同对话密度、分块大小和日期范围的表现。
- Claude与Codex线程导入、重建和修复测试。
- Windows、Linux与不同运行方式的兼容性测试。
- compact、hidden与上下文体积变化记录。

报告是经验数据，不会因为被提交就自动成为Stone Memory的默认配置。修改正式策略前，仍需结合多个用户样本、bad case和回归测试验证。

## 文件命名

建议使用：

```text
YYYY-MM-DD-测试主题-GitHub用户名.md
```

例如：

```text
2026-07-27-miner-model-comparison-example-user.md
```

## 报告模板

复制以下内容创建新文件：

```markdown
# 测试标题

## 基本信息

- 测试日期：
- 提交者GitHub用户名：
- Stone Memory提交或版本：
- runtime：Claude / Codex
- 操作系统：
- 执行通道：API / Subagent
- 模型名与可公开的版本信息：

## 测试目标

这次希望验证什么？

## 输入规模

- 测试日期数量：
- 对话条数：
- 纯对话UTF-8大小：
- 分块数量：
- 既有摘要数量：

不要粘贴未经脱敏的真实对话。

## 测试方法

使用了什么正式 `stmem` 命令？参数是什么？不同方案如何保持输入一致？

## 评价标准

例如：

- 事件覆盖率
- 时间与人物指代准确率
- JSON格式成功率
- 重复摘要数量
- 幻觉或遗漏数量
- feature category准确性
- 执行时间与API消耗

## 结果

使用表格、计数和脱敏后的短样例说明结果。

## Bad cases

记录可以稳定复现的错误，以及它属于模型输出、提示词、切块、解析还是存储问题。

## 结论

这份结果支持什么结论？哪些内容仍不能确定？
```

## 隐私要求

提交前必须删除：

- API Key、Cookie和访问令牌。
- 真实线程ID和完整线程文件名。
- 用户姓名、AI私密称呼及可识别身份的信息。
- 未经当事人同意的对话原文、感情经历和健康信息。
- 本机用户名、家庭目录和私人服务地址。

需要展示样例时，优先使用合成对话；必须使用真实bad case时，只保留解释问题所需的最短脱敏片段。
