# 增强重挖候选审阅原型测试

## 基本信息

- 测试日期：2026-07-27
- 提交者 GitHub 用户名：n5hm9gjc8r-cpu
- Stone Memory 提交或版本：1.1.1 附近的外置只读/候选原型
- runtime：Codex
- 操作系统：Linux 服务端，Windows 浏览器
- 执行通道：兼容 chat/completions API、Codex 子进程
- 模型名与可公开的版本信息：DeepSeek 两个 API profile、GPT 低 reasoning profile

## 测试目标

验证“模型先生成独立候选，用户复核后再按日替换”是否能降低直接重挖的风险，并
验证多模型逐条混选、可选历史规则和长请求异步化能否在不修改原文归档的前提下
稳定工作。

该原型是外置验证，不是建议合入的正式实现。它曾直接复用 Stone reader 与
`MemoryStore.replaceDay()`；根据当前开发约束，正式版本必须把写入收口到
`stmem` CLI，HTTP 与前端不得复制这段逻辑。

## 输入规模

- 正式库中的清洗后对话：约 9,800 条
- 重点测试日期：2 天
- 单日对话量：百条级
- 单日分块数量：由现有完整消息分块逻辑决定
- 既有摘要：数百条

未提交真实对话、候选正文、线程 ID、文件名、人物称呼或私人服务信息。

## 测试方法

1. 使用 Stone 的清洗后 SQLite messages 作为唯一模型输入。
2. 对同一日期、同一 fingerprint 分别运行多个模型，模型之间不共享输出。
3. 候选只写本地私有 JSON，不写正式 feelings / features。
4. 在页面逐条选择多个候选的 feelings / features，生成 hybrid 预览。
5. 检查完全重复去除、20 条上限、来源追踪和 fingerprint 复核。
6. 仅在二次确认后备份 SQLite，并对指定日期执行一次 replaceDay。
7. 全程核对 messages、archive/miner 开关、自动维护开关与作者源码仓状态。

原型没有对应的正式 `stmem` review 命令，这正是 proposal 要补齐的架构缺口。

## 评价标准

- preview 是否在正式写入前可见；
- 不同模型候选是否互相独立；
- hybrid 是否逐条保留来源；
- 完全重复与数量上限是否稳定；
- archive 变化后是否拒绝旧候选；
- apply 是否只替换指定日期；
- 写入前是否生成一致性备份与 SHA-256；
- 长模型请求是否会被代理超时误报失败；
- 是否产生重复模型调用；
- 正式数据库 quick check 与服务状态。

## 结果

| 项目 | 结果 |
| --- | --- |
| 多模型独立候选 | 通过 |
| 逐条混合 feelings / features | 通过 |
| 完全重复稳定去除 | 通过 |
| 20 条 feelings 硬上限 | 通过 |
| 同线程/同日期/fingerprint 约束 | 通过 |
| preview 不写正式记忆 | 通过 |
| apply 前 SQLite backup API | 通过 |
| 单日 replaceDay | 通过 |
| SQLite quick check | 通过 |
| 未触发 rebuild | 通过 |
| 未改变自动开关 | 通过 |

一个 API 模型在单日样本中产生过 15 条 feelings / 8 条 features；另一个已确认
候选产生过个位数 feelings / features。数量差异说明合法 JSON 并不足以决定哪份
应直接覆盖，人工比较和逐条混选具有实际价值。

## Bad cases

### 长 HTTP 请求被代理返回 524

原型最初让 `POST /preview` 等待完整模型响应。反向代理约百秒后返回 524 HTML，
页面把它显示成模型失败，但服务端模型任务随后正常完成并保存了候选。用户若再次
点击，会重复消耗 token。

修正为：

- start 请求约百毫秒返回 202 与 job ID；
- 模型调用在服务端后台继续；
- 页面每 2.5 秒轮询短请求；
- 网络短暂中断有限重试；
- 超时或重启提示先检查候选，避免重复提交。

修正后没有因代理 524 重复调用模型。

### 外置原型的写入层级不符合正式架构

原型验证了备份、fingerprint 与 replaceDay 语义，但 HTTP 服务直接调用了
MemoryStore。正式合入不能复制这一结构，必须先实现可独立验证的 CLI，再由 HTTP
调用 CLI。

### 固定模型名会过期

原型为了内测方便固定了数个模型按钮。正式版本应使用本地 model profiles，并由
用户填写上游真实模型名；核心算法不应依赖会变化的展示名称。

## 结论

测试支持增加“候选审阅层”：它能把模型生成与正式写入分离，让多模型比较、逐条
混选、备份和 fingerprint 复核发生在覆盖旧记忆之前。异步 job 是经过真实代理
超时验证的必要条件。

尚不能从两个日期推断哪种规则或模型应成为所有用户的默认值。作者原版应继续作为
默认提示词；历史、亲密、数量等增强规则必须保持可选，并通过更多脱敏样本与回归
测试后再决定是否进入正式实现。
