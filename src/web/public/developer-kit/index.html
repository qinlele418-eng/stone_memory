01 · 隔离

代码只住在模块里

新模块统一放在 developer-modules/<module-id>/，入口由 module.json 自动注册，无需修改核心 app.js。

02 · 复用

正式能力不重写

读取走授权接口，写入走 CLI；前端、MCP 与自动任务共用同一条业务通道，不为模块另开 companion server。

03 · 归属

数据边界可解释

模块数据按记忆体或全局作用域隔离。候选、草稿与缓存不混入正式记忆库，卸载模块不破坏 Core。

REUSABLE CAPABILITIES

可以直接复用的能力

先复用，再扩展
CLI · 正式写入

stmem module <id> <action> 执行模块命令；已有挖掘、记忆编辑、规则、重建等写能力应调用对应正式 CLI。

常用入口stmem minestmem memory update|anchorstmem rulesstmem rebuildstmem notebookstmem module list|inspect|paths|audit
MCP · Agent 能力

可复用状态、搜索、深度搜索、审计、Notebook、梦境等工具。只读能力可直接调用；写操作仍回到 CLI。

现有工具族stmem_memory_statusstmem_memory_searchstmem_memory_deep_searchstmem_memory_audit_*stmem_notebook_*stmem_dream_*
Watcher · 后台自动化

在 manifest 注册插件并使用 dev- 前缀，由唯一 supervisor 负责启停与自愈，模块不得常驻第二套进程。

标准开关stmem watcher set --thread <id> --dev-<name> on|off状态写入正式配置；实际 worker 由 supervisor 收敛为 ON=1、OFF=0。
SQLite · 独立数据

结构化数据使用模块自己的 module.sqlite 和 migrations，通过上下文解析路径，禁止直接给 Core 数据库加表。

标准落点context.resolveDataPath("module.sqlite")scope: memory 按记忆体隔离，scope: global 全局共享；表迁移放入模块 migrations/。

此外可直接获得当前记忆体、统一主题、页面外壳、返回导航、移动端尺寸和模块数据目录。能力不够时先提 Issue / proposal，不要用旁路代码假装完成。

PR & CI
提交与分发规则

      
    
        
  • 提交 PR 到项目仓库并说明模块目的、权限、数据位置与回滚方式
    • 
        
  • 运行 npm run audit:developer-modules 与模块相关测试
    • 
        
  • 新模块不得携带真实对话、threadId、路径、密钥或服务器地址
    • 
        
  • 桌面端、移动端、自定义主题、无记忆体和接口失败状态均需验收
    • 
        
  • 功能修复应提供复现步骤和回归测试
    • 
        
  • 非功能修复且未明确标注“建议合并”的 PR，默认仅作独立模块分发
    •
